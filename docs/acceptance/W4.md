# W4 acceptance: verification
- Given an ACTIVE credential, when GET /verify/:token, then VERIFIED with institution, holder name, type, dates, "Signed by ...", proof "Not anchored".
- Given suspended, revoked, superseded, expired credentials, then results SUSPENDED, REVOKED, SUPERSEDED (with link), EXPIRED respectively.
- Given an unknown token or a DRAFT, then NOT FOUND.
- Given a signed field edited directly in the DB, then VERIFICATION FAILED and an ops alert, even if the credential is also revoked.
- Given the signing key marked COMPROMISED, then VERIFICATION FAILED.
- Given a suspended institution with a valid credential, then VALID WITH WARNING.
- Given /i/:slug/keys.json, then it lists ACTIVE, RETIRED and COMPROMISED keys with no private material.
- Given a downloaded credential.json and keys.json, when verify-cli runs offline, then it reports valid; after a one-byte change it reports invalid.
- Given 1000 verify requests, then p95 is under 300 ms.
- Given repeated requests from one IP or for one token, then 429 occurs; each check writes a verification_log with a hashed IP.
- Given the public page, then only fields enabled by the institution appear; name and status always do.
