# W1 acceptance: foundations and auth
- Given a fresh clone, when `docker compose up` and install/test run, then Postgres, Mailpit, MinIO start and lint, type-check and tests pass.
- Given the migration applied, when the app role runs UPDATE or DELETE on audit_logs, then it is refused.
- Given a REVOKED credential row, when anyone (including superuser-level app role) sets status to another value, then the trigger raises an error.
- Given RLS and a session for institution A, when querying institution B rows, then zero rows are returned.
- Given a seeded user, when valid credentials are posted to /auth/login, then an httpOnly Secure cookie is set and only a hash of the token is stored.
- Given 5+ wrong passwords, when login is retried, then 429 is returned.
- Given an invite, when accepted once, then a password is set; when accepted again or expired, then it fails.
- Given a reset request for any email, then the response is identical whether or not the user exists.
- Given docs/threat-model.md and ADR 0001, then each listed threat has a mitigation or Phase 1 note.
