# W2 acceptance: institutions, keys, holders, types
- Given a platform admin, when creating an institution, then an Ed25519 key (kid) is generated, the private key stored AES-256-GCM encrypted, and an invite emailed to the first admin.
- Given an institution admin, when patching branding, then changes persist and appear only for that institution.
- Given a key rotation, then the old key is RETIRED, a new ACTIVE key exists, and exactly one key is ACTIVE.
- Given a holder photo upload, then EXIF is stripped, the object is private, and photoSha256 matches the stored bytes.
- Given the two seeded templates, when creating a type with invalid attributes, then 422 is returned.
- Given institution A's session, when reading or writing any B holder, type, key or logo by id, then 404 is returned (automated).
- Given a suspended institution, when its admin logs in, then dashboard actions remain per policy and verification shows a warning (see W4).
